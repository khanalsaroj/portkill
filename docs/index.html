The two step ritual

      
Same problem, different incantation on every OS.

      
Read a PID out of one tool, paste it into another, hope you copied the right number. Then do it a different way on the next machine.


      

        

          
 Before


$ lsof -i :8080
COMMAND  PID   USER   FD  TYPE  NODE NAME
node    54321  saroj  23u IPv4  TCP *:8080 (LISTEN)

$ kill -9 54321

# and on Windows, something else entirely
> netstat -ano | findstr :8080
> taskkill /PID 54321 /F

          
Two commands, one copied number, and a second process on IPv6 that you never noticed.

        


        

          
 After


$ portkill kill 8080

  →  scanning port 8080 …
  ✓  port 8080 freed — killed node (PID 54321)


$ portkill kill 3000 8080 9090

          
One command. Every socket on the port, both address families, verified gone.

        

      

    

  


  


  
  

    

      
Small binary, few surprises.

      
Everything below ships today. There is no plugin system, no config file, and nothing to install alongside it.


      

        

          
          
One command, any port

          
Pass one port or a whole list. portkill resolves the owning processes and frees them in a single pass.

          
$ portkill kill 3000 8080 9090

        


        

          
          
Same binary everywhere

          
One static Go binary per platform. No runtime to install, no package manager required, and no external tools needed at all on Linux.

          

            Linux
            macOS
            Windows
            FreeBSD
          

        


        

          
          
Look before you kill

          
portkill list 8080 prints the process name, PID, protocol and bound address, so you know what you are about to stop.

        


        

          
          
Nothing left behind

          
IPv4 and IPv6, TCP and UDP, and ports held open by more than one process at the same time.

        


        

          
          
Polite first, firm second

          
Every kill follows the same four beats, and the port is re-checked before anything is reported as freed.

          

            
DiscoverEvery socket on the port

            
AskSIGTERM or taskkill

            
EscalateSIGKILL after the grace period

            
VerifyConfirm the port is free

          

        


        

          
          
Built for scripts

          
--json for machine readable output, --quiet for CI logs, and exit codes you can branch on.

        

      

    

  


  
  

    

      
Install

      
Pick your platform, paste one line.


      

        

          
          
          
          
        


        

          

            $curl -fsSL https://raw.githubusercontent.com/khanalsaroj/portkill/main/main/install.sh | bash
            
          

          
Installs to /usr/local/bin, using sudo if it needs to, and falls back to ~/.local/bin. Override either default:

Two commands and a handful of flags.

      
kill frees a port, list tells you what is on it. Everything else is a modifier.


      

        
$portkill kill 8080Free one port
          

        
$portkill kill 3000 8080 9090Free several at once
          

        
$portkill kill -f 5432Force kill, no grace period
          

        
$portkill kill --dry-run 8080Preview without killing
          

        
$portkill list 8080Inspect what is on a port
          

        
$portkill list --json 8080 3000Scriptable JSON
          

      


      

        

          
Behaviour

          

            
-f, --force
Skip the graceful shutdown and hard kill immediately.

            
-n, --dry-run
Show what would be killed, without killing it.

            
--timeout D
Grace period before escalating to a hard kill. Defaults to 3s.

          

        

        

          
Output

          

            
--json
Emit machine readable JSON instead of text.

            
-q, --quiet
Suppress progress output and report only failures.

            
--no-color
Disable colored output. The NO_COLOR variable is honored too.

          

        

      


      

        
0Success, which includes a port that was never in use.

        
1A process could not be killed, or detection failed.

        
2Usage error: a bad flag, or a missing or invalid port.

      

    

  


  
  

    

      
Under the hood

      
It asks first, and it checks afterwards.


      

        

          

            
            
Discover every socket

            
For each port, portkill collects every bound socket: IPv4 and IPv6, TCP and UDP, including ports shared by several processes, then resolves the owning process names.

          

          

            
            
Ask the process to stop

            
Unless you pass --force, each process gets a SIGTERM first, or a plain taskkill on Windows, so it can shut down on its own terms.

          

          

            
            
Escalate only if it has to

            
If the process is still around when the grace period expires, portkill escalates to SIGKILL, or taskkill /F on Windows.

          

          

            
            
Verify before reporting

            
The port is checked again before anything is printed as freed. A success line means the socket is actually gone.

          

        


        

          
How each OS is read

          
    
            
  • 
              
    Linuxkernel /proc tables, then ss, then lsof
    • 
            
  • 
              
    macOSlsof, which ships with the OS
    • 
            
  • 
              
    Windowsnetstat, with tasklist for names
    • 
            
  • 
              
    FreeBSDsockstat, then lsof
    • 
          

          

            
            
Killing a process owned by another user or by the system still needs sudo on Unix, or an Administrator terminal on Windows.
